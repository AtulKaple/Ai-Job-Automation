### 3. Executive Summary & Problem Solved
- **Problem Statement**:
  Patients, rare-disease communities, and caregivers navigating complex health conditions face severe isolation and fragmented clinical knowledge. Existing consumer social networks suffer from systemic privacy vulnerabilities, commercial ad tracking, toxic engagement algorithms, and strict HIPAA/GDPR non-compliance, preventing patients from sharing genuine lived experiences or participating in clinical research without risking identity re-identification. Furthermore, health organizations struggle to bridge real-world patient discussions into structured, anonymized research cohorts due to rigid regulatory compliance bottlenecks.
- **Technical Solution**:
  Architected and built the **Patient Community Network**, a specialized, HIPAA-compliant patient community and clinical insights platform engineered for high-concurrency resilience (2,000+ concurrent users). The platform integrates a zero-trust multi-persona system (Patient, Parent, Caregiver, Medical Reviewer) with granular audience privacy controls, proxy dependent tracking ("Care Recipients"), and server-side identity masking for anonymous support discussions. Engineered an innovative **HIPAA Safe Harbor De-identification Engine** utilizing an **S3 Sandwich Broker Architecture** and **AWS KMS Envelope Encryption (AES-256-GCM)**, enabling automated, zero-leakage research data transfers into the centralized clinical research platform with salted HMAC-SHA256 relational pseudo-ID hashing across 40 database schemas. Designed an edge media compression pipeline (in-browser WASM FFmpeg and Web Workers) slashing network payload by 80%, a horizontally scaled WebSocket infrastructure with Redis Pub/Sub, a multi-layered smart feed with cursor pagination, and an automated weekly clinical intelligence reporting engine delivering multi-tab Excel analytics and NCBI PubMed-curated medical newsletters.

### 4. Deep Architecture Breakdown

#### Module 1 - HIPAA Safe Harbor De-identification System (S3 Sandwich Broker & AWS KMS Envelope Encryption)
- **Architectural Mechanics**:
  To transfer patient community interactions from the Patient Community Network (containing Personally Identifiable Information / PHI) into the centralized research platform without exposing raw databases to each other, engineered a decoupled **Sandwich Broker Architecture** via an intermediary Amazon S3 broker.
- **Consent & Cohort Extraction**:
  A scheduled Node-Cron worker scans across 30+ Mongoose collections (`Post`, `Comment`, `Event`, `Attendance`, `Group`, etc.), strictly gating records where `researchConsent.granted === true` and `research.isEligible === true`. Private chats (`Message`, `Conversation`), auth records (`LoginAttempt`), and security records (`BlockedUser`) are hard-coded for strict exclusion.
- **18-Element HIPAA De-Identification & Relational Graph Hashing**:
  Recursively scrubs all direct identifiers (names, emails, phone numbers, avatars, `cognitoSub`, IP addresses, geolocation coordinates, and exact dates of birth, generalizing DOB to birth year only). To preserve relational integrity across complex graphs without exposing database ObjectIDs, hashes every ObjectID using **HMAC-SHA256** salted with an environment-isolated secret (`DEID_PSEUDO_SALT`). This produces deterministic, irreversible **Pseudo-IDs**, allowing clinical researchers to track an anonymous patient's longitudinal journey across posts, comments, and symptoms over months without reverse-identifying the individual.
- **Application-Layer Envelope Encryption (AES-256-GCM)**:
  Does not rely on static bucket encryption. Dynamically requests a 256-bit cryptographic data key from AWS KMS (`DEID_KMS_KEY_ID`). Encrypts the scrubbed JSON payload in application memory using **AES-256-GCM**, generating an encrypted ciphertext buffer, Initialization Vector (`iv`), and Authentication Tag (`authTag`). Plaintext data keys are immediately purged from Node.js memory. The encrypted payload, along with the KMS-encrypted data key, is uploaded to the S3 broker bucket.
- **Machine-to-Machine HMAC Webhook Dispatch**:
  Social signs a webhook notification to Hub’s `/api/deid/ingest-webhook` using a shared HMAC-SHA256 signature (`DEID_WEBHOOK_SECRET`) with timestamp verification to prevent replay attacks. Hub authenticates the request, fetches the S3 object, calls AWS KMS (explicitly routed to `us-east-2`) to decrypt the data key, decrypts the AES payload, and executes high-throughput MongoDB `bulkWrite` upsert operations into dynamically generated research schemas (`DeidUser`, `DeidPost`).

#### Module 2 - Horizontally Scaled Real-Time Communications & WebSocket Presence Layer
- **Architectural Mechanics**:
  Built on Socket.io 4.8 and decoupled across multi-core Node.js cluster processes and EC2 instances via `@socket.io/redis-adapter` backed by an AWS ElastiCache / Redis cluster with ioredis duplicate client instances.
- **Connection Handshake Authentication**:
  Socket handshake middleware extracts incoming bearer tokens and validates them against AWS Cognito User Pools via `aws-jwt-verify` using JWKS key caching and clock skew tolerance. Rejects unauthenticated connections before protocol upgrade.
- **Stateful Presence & Clustered Event Routing**:
  Maintains active connection maps (`userId` $\to$ `socketId`) and partitions real-time rooms into scoped channels (`user:${userId}`, `conversation:${convId}`, `group:${groupId}`). Emits real-time typing indicators, read receipts, event check-in counts, and multi-surface notifications across cluster workers via Redis Pub/Sub broadcast channels, with automated fallback to in-memory adapters during transient network partitions.

#### Module 3 - Multi-Layered Smart Feed Algorithm & Base64 Cursor Pagination
- **Architectural Mechanics**:
  Designed a two-tier hybrid recommendation feed in `smartFeedService.js` to eliminate feed abandonment for both established users and cold-start newcomers.
- **Tier 1 (Personalized Social Graph)**:
  Prioritizes content using weighted relational scoring: Accepted Friends (Weight 1.0) > Explicit Following (0.8) > Joined Community Groups (0.6) > Subscribed Disease Slugs (0.5) > Mutual Group Co-members (0.3). Employs Redis caching for user connection lists and group memberships to eliminate expensive repetitive joins.
- **Tier 2 (Cold-Start Contextual Discovery)**:
  For users with zero follows/friends, dynamically constructs a context-aware discovery feed based on IP geolocation matching (`geoip-lite`), medical diagnosis matching (`User.diseases`), shared health interest tags, and high-engagement community fallbacks.
- **High-Performance Pagination**:
  Replaced high-offset MongoDB `skip`/`limit` operations (which cause linear query degradation at scale) with deterministic, Base64-encoded opaque cursor pagination (`encodeCursor`/`decodeCursor`) operating over multi-key compound indexes (`{ groupId: 1, createdAt: -1 }`, `{ authorId: 1, createdAt: -1 }`), guaranteeing stable sub-100ms response times at any feed depth.
- **Server-Side Anonymity & Statistical De-Anonymization Shield**:
  Enforces post privacy at the database query and service layer. If `isAnonymous: true`, masks author metadata to `"Anonymous User"` and strips all avatars and bios before payload serialization. Automatically blocks targeted audience exclusion lists on anonymous posts, preventing malicious users from deducing anonymous authors through set-difference correlation attacks.

#### Module 4 - Client-Side Edge Media Optimization (WASM FFmpeg & Web Workers)
- **Architectural Mechanics**:
  To protect backend infrastructure from heavy video transcode compute spikes and reduce cloud storage bandwidth egress, offloaded media processing to client hardware before upload initiation.
- **WebAssembly Video Transcoding**:
  Integrated `@ffmpeg/ffmpeg` 0.12 and `@ffmpeg/util` running an in-browser WebAssembly core (`ffmpeg-core.wasm`). Automatically transcodes uploaded video formats into standardized MP4 containers utilizing `libx264` encoding, Constant Rate Factor `crf=28`, ultrafast preset, and dynamic downscaling (`scale=min(720,iw):-2`). Provides real-time rendering progress bars via WebAssembly event hooks.
- **Multi-Threaded Image Compression via Web Workers**:
  Leverages `browser-image-compression` configured with `useWebWorker: true`. Offloads image canvas resizing and matrix operations into dedicated background Web Workers, compressing raw mobile camera photos down to $<1\text{MB}$ ($1920\text{px}$ maximum dimension) without blocking the React main UI thread, preserving a stutter-free 60 FPS user experience. Slashes client payload sizes and S3 storage volume by 75%–80%.

#### Module 5 - Cross-Platform Mobile Architecture & Apple Secure Enclave Biometrics
- **Architectural Mechanics**:
  Packaged the responsive React/TypeScript application into a native iOS mobile application using Capacitor 8 runtime (`@capacitor/core`, `@capacitor/ios`), bundled under application identifier `com.patientcommunity.app`.
- **Hardware-Isolated Face ID Security**:
  Implemented Apple Face ID biometric authentication via `@capgo/capacitor-native-biometric` (v8.6). Biometric verification runs strictly inside Apple's hardware-isolated **Secure Enclave**; the application never captures or stores facial vector data.
- **Hardware-Backed Keychain Storage**:
  Stores AWS Cognito authentication tokens (`idToken`, `accessToken`, `refreshToken`) encrypted in the **iOS Keychain** bounded to the application domain (`com.patientcommunity.auth`).
- **Privacy Lock Lifecycle Screen**:
  On mobile app launch or cold resume, engages `BiometricPromptModal`, completely blocking unauthorized viewing of sensitive patient discussions, condition tags, and messages. Upon successful biometric scan, triggers proactive token refresh against AWS Cognito endpoints to ensure continuous, valid session state.
- **Cross-Platform Shared Cookie Single Sign-On (SSO)**:
  Implemented shared-domain cookie authentication (`domain: '.sidlabs.net'`) utilizing `HttpOnly`, `Secure`, and `SameSite: 'none'` flags. Users authenticated on the Patient Community Network navigate seamlessly to the Healthcare Research Application without re-entering credentials, achieving unified enterprise SSO while preventing client-side script access (mitigating XSS).

#### Module 6 - Automated Clinical Intelligence Reporting & Server-Rendered Charts (ExcelJS & ChartJS Canvas)
- **Architectural Mechanics**:
  Engineered an automated weekly analytics pipeline (`weeklyAdminAnalytics.cron.js`) running via Node-Cron every Friday at 8:00 AM.
- **Multi-Model Data Aggregation**:
  Gathers and correlates metrics across 40 Mongoose models, tracking platform growth, active users, post engagements, symptom discussions, geographic dispersion, and Clinical Study Readiness cohorts (consented users, profile completion rates, active retention curves, and moderation safety logs).
- **Server-Side Chart Generation**:
  Utilizes `chartjs-node-canvas` and `chart.js` to render ultra-high-resolution $2000 \times 700$ PNG analytical charts in pure Node.js memory without requiring headless Chrome or Puppeteer, reducing memory footprint by over 90%.
- **8-Tab Dynamic Excel Synthesis**:
  Synthesizes rich Excel workbooks using `ExcelJS`, embedding custom-rendered charts and generating 8 structured sheets: (1) Analytics Overview with KPI cards, (2) User-Level Analytics, (3) Content & Engagement, (4) Region-wise Activity, (5) Daily Breakdown, (6) Moderation Audit, (7) Retention Cohorts, and (8) Clinical Study Readiness Dashboard. Automatically formats and dispatches the workbook as an email attachment to administrative leadership via AWS SES (`@aws-sdk/client-ses`).

#### Module 7 - NCBI PubMed Literature Integration & Medical Weekly Newsletter Engine
- **Architectural Mechanics**:
  Developed a clinical literature curation engine connecting patient support groups with peer-reviewed medical science via the NCBI PubMed REST API (E-utilities).
- **Medical Keyword Extraction & PubMed Pipeline**:
  Extracts medical taxonomy keywords from group discussions and condition metadata; queries PubMed via `esearch` for articles published in the preceding 14 days, fetches XML summaries via `esummary` and `efetch`, and parses article abstracts and persistent PubMed URLs (`https://pubmed.ncbi.nlm.nih.gov/${id}`).
- **Cold-Community Resilience**:
  When a rare-disease support group has low organic activity, automatically queries PubMed with the group's disease tag to fetch top 5 peer-reviewed publications, ensuring patients receive continuous clinical education even during quiet discussion periods.
- **LLM Synthesis & Two-Phase Dispatch Worker**:
  Feeds PubMed abstracts and top community discussions into Groq LLaMA / Anthropic Claude to compile structured medical briefings with source citations. Implements a two-phase worker: pre-generates drafts 4 hours prior in MongoDB (`status: 'scheduled'`), alerts group moderators via email for review/editing, and executes scheduled dispatch to subscribed members with zero runtime AI generation at send time.

#### Module 8 - On-Premise Semantic Vector Search (RAG Pipeline & Transformers.js)
- **Architectural Mechanics**:
  Built an AI Search feature enabling semantic natural language discovery across posts, forum threads, and comments.
- **Zero-Leakage Local Embeddings**:
  Executes `@xenova/transformers` with `all-MiniLM-L6-v2` locally inside the Node.js server process to generate 384-dimensional dense vectors. Raw patient healthcare text is never transmitted to external third-party vectorization APIs.
- **Vector Indexing & Hybrid Retrieval**:
  Stores embeddings in MongoDB Atlas Vector Search utilizing Cosine Similarity indexing. Queries return top-k matches filtered against user permissions and group memberships.
- **PII-Scrubbed RAG Summarization**:
  Strips all user identifiers and routes anonymized snippets to Groq LLaMA / Claude with strict clinical prompting, returning concise syntheses with explicit bracketed source citations (`[Source ID: 123]`) and caching responses in Redis for 24 hours.

#### Module 9 - Enterprise Defense-in-Depth Security, Account Protection & RBAC
- **Architectural Mechanics**:
  Hardened the platform against brute-force account takeovers and privilege escalation through multi-tiered middleware.
- **Two-Tier Brute-Force Mitigation**:
  Tier 1 enforces IP-level throttling (20 requests per 15-minute window via `express-rate-limit`). Tier 2 tracks per-account authentication failures in `LoginAttempt.js`: triggers mandatory Google reCAPTCHA challenges after 3 consecutive failed logins, and enforces automated 1-hour account lockouts (`lockUntil`) after 10 consecutive failures.
- **Role-Based Access Control (RBAC) & Multi-Persona Architecture**:
  Supports 6 system roles (`admin-user`, `moderator-user`, `patient-user`, `caregiver-user`, `researcher-user`, `reviewer-user`) mapped from Cognito groups, alongside 5 community personas (Patient, Parent, Caregiver, Other with write-in roles, and Medical Reviewer).
- **Care Recipient (Ward) Management**:
  Provides first-class data structures (`User.wards`) allowing parents and caregivers to manage dependents' health profiles and author proxy posts ("posted for [Name]"), automatically sanitizing care recipient names to `"Care Recipient"` during anonymous post creation.

#### Module 10 - Gamified Engagement Engine & Anti-Exploitation Tokenomics
- **Architectural Mechanics**:
  Incentivizes constructive health discussions through a non-blocking gamification subsystem.
- **Asynchronous Fire-and-Forget Architecture**:
  The token service operates asynchronously following HTTP response completion (`res.finish`), ensuring token calculation never adds latency to primary API mutation lifecycles.
- **Anti-Exploitation Safeguards & Transaction Ledgers**:
  Awards granular tokens across 18 distinct activities (creating posts +10, comments +5, forum replies +7, daily logins +5, completing surveys +25). Maintains an immutable transaction audit log (`TokenTransaction`) with per-action daily rate ceilings, thwarting bot spam and point farming. Automatically unlocks milestone badges and maintains paginated global and friends-scoped leaderboards cached in Redis.
