#### 3. Executive Summary & Problem Solved
- **Problem Statement**:
  Creating bank-grade Detailed Project Reports (DPR) and Credit Monitoring Arrangement (CMA) dossiers for corporate debt financing, term loans, and working capital limits in corporate banking typically requires Chartered Accountants (CAs) and investment bankers to spend 35–60 hours manually cross-linking multi-tab financial spreadsheets. Any modification in capital expenditure (CapEx), debt moratorium, plant capacity, or raw material bill-of-materials (BOM) introduces catastrophic `#REF!` errors, broken circular dependencies, and mismatched financial ratios (e.g., DSCR, ROCE, Current Ratio, Break-Even Point), risking loan rejection by underwriting committees. Furthermore, gathering technical quotation matrices, land/building civil estimates, and multi-vendor machine invoices from non-technical business clients is slow and unstructured.
- **Technical Solution**:
  Architected a high-throughput full-stack financial modeling platform and desktop/cloud hybrid application that automates the generation of compliant, multi-tab bank project appraisal dossiers. The platform combines:
  1. A 15-step interactive financial wizard in Next.js 15 / React 19 featuring client-side CSV ingestion for equipment quotation bills and real-time state synchronization via Zustand.
  2. A dedicated 8,000+ line spreadsheet compiler built on Node.js and ExcelJS that dynamically parses, splices, and regenerates 14+ tightly coupled financial worksheets (Master Sheet, Annexures I through VII, Tables T-1 to T-13, and Projected CMA Statements).
  3. A custom formula repairing engine (`solveRefErrors`) that performs AST-like coordinate translation and reference tracking to eliminate `#REF!` errors across cross-sheet formula dependencies during dynamic row splicing.
  4. An offline-capable Electron 42 desktop distribution featuring a custom `app://` privileged protocol for local execution, complemented by a secure token-based external intake portal backed by MongoDB TTL auto-expiring indices.

#### 4. Deep Architecture Breakdown

- **Module 1 - Multi-Stage Financial Modeling Wizard & Client State Pipeline**:
  - Implemented a 15-step synchronized financial entry system in `frontend/src/app/dashboard/project-report-generator/page.tsx`: Step 0 (Configuration/Company Selection), Step 1 ("M" - Master Company Profile, Incorporation, CIN, Promoters), Steps 2–6 ("A-1" to "A-5" - Land & Site Development, Building & Civil Works, Plant & Machinery, Miscellaneous Fixed Assets, Contingencies), and Steps 7–14 ("T-1" to "T-10" - Cost of Project, Means of Finance, Production Capacity, Sales Realization, Utility Costs, Working Capital MPBF calculations, Loan Repayment Amortization, and Projected Financial Statements).
  - Designed dynamic Bill of Materials (BOM) tracking supporting finished product mixes with customized burning loss percentages, captive consumption ratios, and multi-tier raw material requirements per metric ton.
  - Built a client-side CSV ingestion pipeline using PapaParse with custom `beforeFirstChunk` header sniffing that dynamically identifies quotation table headers (`S.N.`, `Equipment`, `Supplier's Name`, `Negotiated Price`), normalizing arbitrary vendor quotes into validated form state.

- **Module 2 - Spreadsheet Synthesis Engine & Dynamic Matrix Splicing (`backend/routes/excel.js`)**:
  - Developed an 8,000+ line spreadsheet compiler using ExcelJS that loads pre-formatted banking templates (`template8.xlsx`, `templateT8Existing.xlsx`) and streams compiled binary workbooks (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`) directly to client memory buffers without disk overhead.
  - Utilized `sheet.spliceRows` to dynamically insert variable numbers of finished products, raw material sub-tables, and equipment lines into static worksheets without corrupting layout formatting.
  - Automatically synthesized grouped sub-tables for each product line (`(A)`, `(B)`, `(C)...`) with dynamic Cambria typography, custom border formatting, and formula assignment linking directly to the main production schedule.

- **Module 3 - Cross-Sheet Formula Dependency Graph & `#REF!` Auto-Correction Algorithm (`solveRefErrors`)**:
  - Solved the cascading formula corruption inherent in spreadsheet libraries where dynamic row insertions invalidate static inter-sheet cell addresses.
  - Built algorithmic scan functions (`findRowContaining`, `findRowContainingFormula`, `findRowContainingExactFirst`) to dynamically locate shifting key row anchors across 14+ interconnected worksheets (`T3&T4`, `T-11`, `T9&T10`, `F1`, `F2`, `F3`, `F4`, `Project CMA`, `Master Sheet`, `Annexure-I` to `Annexure-VII`).
  - Reconstructed dynamic formula strings (e.g., `'T-11'!${col}${t11Row}`, `SUM(...)`, closing stock raw material carry-forwards, advance to suppliers, and purchase values) and committed cell mutations atomically prior to buffer export, achieving zero broken references.

- **Module 4 - Debt Amortization & CMA Working Capital Engine (`backend/routes/t8ExistingExcel.js` & Annexure T-8)**:
  - Engineered an Indian Financial Year (April–March calendar) multi-loan debt servicing engine capable of parsing dates (`Apr'25` to `Mar'34`) and mapping amortization schedules over 10-year projection horizons.
  - Computed monthly interest accruals (`Interest = C * D8 / 12`), drawdowns, principal repayments, carry-forward obligations, and closing balances for both proposed project term loans and legacy institutional debt.
  - Automated Table T-6 Working Capital Assessment based on Nayak and Tandon committee norms, modeling holding periods for raw materials, work-in-progress (WIP), finished goods, and book debts against bank margin limits to compute Maximum Permissible Bank Finance (MPBF).

- **Module 5 - Dual-Target Desktop Distribution Architecture (Electron + Next.js SSG)**:
  - Packaged the Next.js static export (`out/`) into an Electron 42 desktop application configured with `electron-builder` and an NSIS Windows installer.
  - Registered `app://` as a privileged protocol (`protocol.registerSchemesAsPrivileged` with `standard`, `secure`, `supportFetchAPI`) and configured `protocol.registerFileProtocol('app', ...)` to map dynamic route requests to local filesystem HTML files, bypassing CORS and web-server overhead.
  - Provided offline-first execution for financial practitioners handling confidential client audits without requiring constant Internet connectivity or external hosting.

- **Module 6 - Zero-Trust External Client Intake & MongoDB TTL Security Pipeline**:
  - Created an ephemeral client data-collection workflow allowing CAs to generate time-limited external links with cryptographically random 20-byte hex tokens (`crypto.randomBytes(20)`).
  - Implemented MongoDB TTL indexing (`{ expireAfterSeconds: 0 }` on `expiresAt`) in `backend/models/LinkSchema.js`, automating self-pruning of expired client links after 72 hours with zero database bloat.
  - Built dynamic endpoint switching (`getBackendUrl` / localStorage fallback) enabling instant transition between local LAN and remote cloud backend microservices.
